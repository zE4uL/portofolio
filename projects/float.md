# Float — A multi-product design system for now.gg

**Company:** now.gg / BlueStacks
**Years:** 2023 → present
**Role:** Lead / Sole DS Designer (parent + 3 of 4 children); architect + walkthrough lead for the remaining 2 children
**Pseudo-title:** Design System Officer (DSO) — awarded by Principal Designer
**Tier:** 1 — co-headline with nowStudio (Float is the foundation that made nowStudio possible)

---

## What it is (public context)
Float is the multi-product design system that powers the now.gg family. It started in 2023 when I was handed an existing thin DS for the now.gg website and asked to revamp + document it. As nowStudio came online in parallel — light theme, dev-aimed audience — I proposed a **parent/child architecture**: one base DS (Float) owns the brand layer (color, type, spacing, radius, elevation, icons, atom components); each product gets its own child DS (Float Studio, Float Website, Float Player, Float Gameroom) that **inherits** the parent and overlays its own personality (organisms, patterns, custom text/colour styles).

This let now.gg's website lean into a fun, gamer-first design language while nowStudio kept an editorial sans-serif suited to game devs — same brand DNA, distinct product personalities, no fork.

**The four children:**
- **Float Studio** — nowStudio (light theme, editorial sans, B2B dev tooling)
- **Float Website** — now.gg website (dark theme, fun typeface, gamer audience)
- **Float Player** — now.gg cloud player
- **Float Gameroom** — experimental product

## My role / contribution
- **Solo lead** on **base Float**, **Float Studio**, and **Float Gameroom** (Figma library, tokens, components, documentation).
- **Architect + walkthrough lead** for **Float Website** and **Float Player** — designed the inheritance approach, ran the team walkthrough, and other designers built those children following the model.
- Researched best-practices and benchmarked top-company design systems before defining the architecture.
- **Pioneered Figma token tooling pre-native-Variables** — used a 3rd-party plugin to create and manage ~100 tokens before Figma shipped Variables (June 2023).
- Wrote in-Figma anatomy documentation for every base atom.
- Established lightweight governance: components are promoted into base on demand; changes get an impact discussion before merging.
- Ran internal workshops on token usage, DS documentation, and child-DS creation.
- Held lead-designer feedback rounds before each child DS launch.
- **Pseudo-titled "Design System Officer"** by my Principal Designer / Design Manager in recognition of the contribution.

## Why it matters for senior/lead positioning
- **Design system architecture** (parent/child inheritance) is genuinely senior-level systems thinking — it's the move that lets one DS scale to N products without forking.
- **Pre-Variables tokenisation** demonstrates technical curiosity and pioneering work — this isn't catch-up, it's earlier than the platform.
- **Architect → evangelist** narrative (workshops + walkthroughs that enabled other designers to build child DSes) is the exact behaviour a Lead-track candidate is hired for.
- The **DSO pseudo-title** is third-party validation, not self-described.
- BluePrint proves the approach is **portable** to a different org / product line.
